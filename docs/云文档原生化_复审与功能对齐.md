# 云文档原生化复审与功能对齐

日期：2026-09-07。对照 `we-meet-android` 的 `feat/docs-native`（起点 `b0708aa`）和 `we-meet-docs` 的 `feat/docs-native`（起点 `00fa313d`）。Web 基线是本地 docs 分支的真实组件、REST serializer、权限实现和 BlockNote 0.51.4 源码，不以上游最新功能或设计稿中的勾选代替验收。

## 设计结论

继续采用原生管理/阅读 + Web 协作编辑器。撤回“管理/评论/版本全部应该原生”“90% 已一致”“多人协同零开发成本”等判断；这些没有可复现的测量依据。原方案的人日估算是立项预估，不是当前剩余工作量。

必须保留的边界：

- 原生层不写 Yjs 正文，包括历史版本恢复。Web `ModalConfirmationVersion` 在保存后还对 provider 的 Y.Doc 执行 `revertUpdate`；少这一步会让存储快照与正在协作的文档不一致。
- `formatted-content` 读取持久化正文并调用转换服务，没有已验证的 ETag/304 契约。原生阅读是快照阅读；Web 每分钟保存再加原生每 30 秒轮询，不能承诺 PC 输入后 30 秒内可见。
- 编辑态标题与正文由同一个 Web 页面维护；原生详情的重命名可以保留。两个标题输入框各自保存会产生重复 UI 和旧状态覆盖。
- 桥接完成需要请求、响应和失败语义，不能只在 App 声明消息名。保存请求带 `docId/requestId`，收到成功响应才退出；超时或失败保留页面。保存期间继续输入必须再次保存后才响应成功。
- 原生持久化离线阅读尚未实现。未来缓存必须先解决账号隔离、登出清理和失权后的内容处理，不能直接套用“JSON 文件 + TTL”就宣称离线可用。
- 票据 URL 已可直接 GET，不新增 ticket 明文字段；只返回明文票据不能省去换 Cookie 的步骤。

## 已修改的实现

| 领域 | 原实现缺口 | 本次处理与依据 |
|---|---|---|
| 保存退出 | App 发 `wemeet-save-now` 后立即 destroy；Web 无接收方 | `useSaveDoc` 实现保存响应；App 系统返回与顶栏关闭共用守卫，15 秒超时可重试，失败不销毁 |
| 保存状态 | 远端事务或前一次保存成功会清掉后续本地修改标记 | 使用本地变更序号与已保存序号；测试保存期间新增编辑、远端事务、失败重试 |
| 版本 | 旧 base64 原生 PATCH，缺少 Y.Doc 回退；列表无预览 | 删除原生正文写 API；原生版本列表打开 `version` 指定的 Web 预览，恢复沿用 Web 流程；分页遵守 `is_truncated` |
| 评论数据 | 写入 inline 数组，但 Web 的 `initialContent` 需要 block 数组 | 新评论/回复写 paragraph blocks；Web 兼容旧 Android inline/字符串，不改历史数据 |
| 评论权限 | `resolved_by` 当用户对象；`react` 与后端 `reactions` 字段不符；取消表情的 Retrofit DELETE 不允许 Body | DTO 与实际 serializer 对齐；DELETE 改 `@HTTP(hasBody=true)`；服务端 reaction.users 不含 ID，撤销依据 `user_already_reacted` 明确响应兼容，不按姓名猜身份；解决/重新打开及表情按 abilities 控制 |
| 评论功能 | 失败即丢草稿、静默失败；无删除入口和已解决筛选 | 成功后才清空新评论/回复；错误提示；评论删除确认与权限控制；打开/已解决筛选 |
| 评论跨端刷新 | Web 靠 awareness ping，原生 REST 不会发 ping | Web 可见页面 30 秒补查线程、切回前台补查，销毁移除定时器；原生评论面板可见时周期刷新 |
| 评论定位 | App 页面加载后发一次无人处理的消息 | Web 编辑器在线程就绪后消费 URL `thread` 并调用 CommentsExtension；恢复编辑态评论侧栏可见性 |
| 会话 | 增量 Set-Cookie 覆盖 session；HTTPS 缺 Origin/Referer；普通 403 和未登录混淆 | 同源 Cookie 合并/过期过滤，写请求补 CSRF 来源并省略 HTTPS 默认端口（线上新建已复测）；明确认证/CSRF 错误单飞重建一次；票据 URL 不进入 docs HTTP 日志 |
| 阅读刷新 | 返回编辑页只刷新标题；轮询只查正文；失权继续保留数据 | 前台刷新元数据和正文；顺序执行、互斥防止重叠；权限撤销/404 清除详情，普通网络失败保留现有内容 |
| 权限入口 | 按 update/retrieve 等少数字段猜所有功能 | 编辑、评论、版本、分享管理/查看、离开、子文档按各自服务端 abilities |
| 搜索与列表 | 搜索仅第一页；刷新与旧 loadMore 可交错追加；搜索被状态栏遮挡 | 搜索续页和系统栏 inset；列表刷新取消旧分页并隔离响应代次、结果按 id 去重；创建/删除/恢复/移动后刷新列表与计数；收藏视图撤销收藏后刷新 |
| 收藏与层级 | 有收藏动作，没有收藏视图；详情不能进入/创建子文档 | 抽屉新增收藏视图；详情菜单新增原生子文档分页列表和新建 |
| 移动 | 首个“可见根”不一定是真根；不可写节点仍可选；200 条截断 | 顶层目标需 depth=1；目标子级需 move 权限，排除当前子树；取完候选分页 |
| 分享 | 继承结果当本地链接设置；硬编码权限选项；成员返回数组却按分页对象解析；邀请首屏截断 | 本地 reach/role 与 `link_select_options` 对齐；管理/离开按 abilities；成员按实际无分页数组契约读取、邀请完整分页；邀请失败保留邮箱、操作错误提示 |
| 面板布局 | 评论半展开时输入框和空态落到屏幕外 | 评论固定可用高度并为键盘留空间，输入区固定底部；评论/版本/分享/移动/子文档直接完整展开 |
| 原生表格与降级 | 新版 tableCell 对象无法读取；解析失败被当空白文档 | 兼容旧单元格数组和新对象；合并单元格保留 Web 降级；非法非空正文显示不支持占位 |
| 链接路由 | 任意 URL 中出现 UUID 都被当作 docs 文档 | 仅 `/docs/<uuid>/`，调用入口校验配置的 docs 来源；媒体 UUID 与外部同形路径不误路由 |

## 尚未完整对齐

以下是明确的剩余工作，不计入上述已完成范围：

1. **原生富文本评论编辑、选区锚定**：本次支持评论阅读/新建/回复/删除/解决/表情；保留 Web 编辑入口，不能把格式化评论转换成纯文本后直接覆盖。完整原生编辑需要保留 block/inline 结构和草稿。
2. **树和文档管理交互**：当前通过逐层子文档浏览；Web 的常驻树、拖动排序、批量操作、复制包含子树/权限选项、祖先面包屑仍需单独补齐。移动目标大量数据的渐进加载与重试体验仍可改善。
3. **阅读保真和性能**：复杂合并表格、多列、视频/PDF、未知 inline mark、长文目录/文内搜索及媒体错误重试需要样例验收；目前依靠 Web 入口补足。不能把所有“没有崩溃”的块都计为支持。
4. **分享细节**：完整继承权限说明、可选添加成员角色、待审批申请管理、邀请编辑和成员搜索体验还需与 Web 逐项验收。
5. **编辑器生命周期**：旋转/折叠导致 Activity 重建、进程被系统回收、上传中退出、长时间离线重连、系统返回先关闭 Web 浮层等仍需真机专项；保存确认不等于覆盖这些场景。
6. **离线与实时阅读**：原生账号隔离持久化缓存、离线提示、条件请求后端契约尚未实施。需要实时阅读的场景使用 Web provider，不用缩短 REST 轮询冒充实时同步。
7. **设备与无障碍**：1.3/1.5/2.0 字体、横屏/平板/折叠屏、键盘、暗色和 TalkBack，按 `app-ux-device-matrix.md` 验证。编译与 token 护栏不替代这些检查。

## 第三轮实施与联调（2026-09-07）

本轮实施第二轮确定的 P0 核心机制，并补齐直接相关的刷新、草稿和链接权限问题。两个仓库均在 `feat/docs-native`，基于 Android `ad91a2d`、docs `e012c8cd` 的工作区修改；本节不表示第五节所有 P0/P1/P2 验收项已经完成。

### 已实现

| 范围 | 最终行为 |
|---|---|
| v2 握手 | 每次主页面载入生成实例身份；同源、docId、instanceId 校验通过才显示可交互画布。10 秒未就绪显示重试提示；旧前端不能提前接受输入 |
| 退出协调 | 每次关闭都请求保存；Web 失焦并冻结输入，等待标题/上传/评论提交/历史恢复，再检查未发表评论和未完成附件，最后 flush Y.Doc。Web 12 秒、App 15 秒超时，失败保留画布；旧回执不关闭新页面 |
| 标题与重试 | 标题写入串行，失败标题可重试；超时后继续编辑时，新标题仍排在旧重试之后，避免旧响应覆盖新标题 |
| 导航与只读 | Web 链接和 Next 程序化路由纳入保存后跳转；只读页面也有握手和保存协调器，权限变化时不以新 reader 实例代替原协调器 |
| 历史恢复 | 保留 Web REST + `revertUpdate`；等待操作完成，禁用重复恢复，失败保留确认框。无原生正文 PATCH |
| 账号隔离 | 持久化 owner、账号代次和独立 transport；引导/API/Cookie/媒体回填校验代次，旧请求取消；取消异常继续抛出。禁用 HTTP 连接失败时的透明重试，认证明确拒绝时仍仅重建一次 |
| 登出清理 | 同步失效原生会话、销毁 Docs WebView、停止媒体 loader、清内存缓存；两种登录方式都等待 WebView Cookie 清理完成后导航。移除旧媒体磁盘缓存，新 loader 不使用磁盘缓存 |
| 前台刷新 | 原生详情与评论只在 RESUMED 且存在可用网络时轮询；生命周期取消传播到请求。详情合并刷新意图与必要尾随刷新，失败退避，支持秒数形式 Retry-After；相同正文不重复解析，不再周期性弹“内容已更新” |
| 评论草稿 | 草稿归 ViewModel/SavedStateHandle；新评论与各线程回复分开存储，关闭面板不清空，只在发表成功后清对应草稿 |
| 页面重建 | 保存当前文档 URL，重建后提示检查最后修改；旋转配置仍保留 WebView。没有声称恢复进程死亡前未持久化的 Y.Doc |
| 受限链接 | 修正 `link_select_options.restricted = null` 的契约；切回“仅限特定成员”不要求选择角色，写请求省略 `link_role`。现场确认：传角色值及显式 null 均返回 400；省略字段成功 |

网络判断以具备 INTERNET 能力的默认网络为依据，不要求 Android 公网探测获得 VALIDATED。联调设备在可以访问 Docs 时被系统标记为 PARTIAL_CONNECTIVITY，强制 VALIDATED 会误停刷新。真正的服务不可达仍由请求错误与退避处理。
