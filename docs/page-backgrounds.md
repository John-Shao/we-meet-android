# 移动端 UI 设计规范：页面层级与配色

本规范是项目移动端页面配色的统一规则，新增和改动页面均须遵循。设计、开发和验收以本页为准；各移动端实现使用对应平台的主题 token。Android 的组件与代码约束另见[设计规范](设计规范.md)。

## 1. 按页面层级划分背景

浅色主题以「消息」一级页和「新建日程」二级页为参照。这里的“深色”指相对白色更深的浅灰底，不是深色主题。

| 页面层级 | 系统状态栏及顶部固定区域 | 下方滚动区域 | 底部模块导航栏 |
| --- | --- | --- | --- |
| 一级：消息、日历、会议、通讯录、云文档、任务 | 浅灰 | 白色 | 显示，白色，与内容底衔接 |
| 二级及更深：新建、详情、设置、搜索等独立页面 | 白色 | 浅灰 | 隐藏 |

- **分界位置**：以顶部固定区域与下方滚动区域的交界为颜色分界。标题、固定操作区、固定筛选栏属于头部；内容区即使为空、加载中、出错或不足一屏，也必须保持该层级的内容底色并铺满可用区域。
- **顶部衔接**：系统状态栏背后的底色必须与当前页面固定头部一致，包含顶部安全区；不能露出上一级页面的底色。滚动后头部仍保持规定底色。
- **底部衔接**：一级页面白色内容底延续到六模块底部导航栏。二级及更深页面占据完整页面空间，不得被模块导航栏遮挡，也不得留出该导航栏的空白占位。
- **返回恢复**：返回一级页面时恢复模块导航栏与浅灰状态栏。顶栏返回、系统返回行为一致，切换模块或退出子页面后不能残留其配色和导航状态。

这里的“底部模块导航栏”指消息、日历、会议、通讯录、云文档、任务六个入口，不是操作系统的手势条或导航键。页面层级按用户所见的完整页面判定，即使详情在模块内部切换显示，也必须遵循二级页规则。

## 2. 日历例外与内容语义

- **日期栏例外**：日历中可左右滑动的日期栏仍为白色，与下方内容及底部模块导航栏同底色，颜色分界在日期栏上方；会议室的日期栏同样处理。
- 日历和会议室的时间网格保留工作时间、非工作时间、选中日期、占用状态等语义底色，不用整块背景替换这些信息。会议室详情仍须遵循二级页面的白色状态栏和隐藏模块导航栏规则。
- 浅灰滚动区域中的表单卡片、信息卡片可保持白色；区域底色与卡片底色分别处理。
- 视频、摄像头预览、封面图片等专用内容保留各自的语义色与显示方式；弹窗、底部弹层按相应组件规范处理。
- 深色主题沿用相同的区域和层级关系，取对应主题 token；不要硬编码白色、灰色，也不要直接交换整套深浅主题。

## 3. Android 实现映射

| 语义 | Android token | 当前浅色主题值（仅供识别） |
| --- | --- | --- |
| 浅灰区域底 | `MaterialTheme.colorScheme.background` | `#F6F6F6` |
| 白色表面底 | `MaterialTheme.colorScheme.surface` | `#FFFFFF` |

色值以 [Color.kt](../core-design/src/main/java/com/we/meet/ui/theme/Color.kt) 为准，调用处使用 token。

- 常规二级及更深页面使用 [WeMeetTopBar](../core-design/src/main/java/com/we/meet/ui/components/WeMeetTopBar.kt) 默认的 `surface` 底色，不设透明头部；一级页固定头部显式使用 `background`。
- 在 [MainTabScreen](../app/src/main/java/com/we/meet/ui/main/MainTabScreen.kt) 内部打开完整子页面时，须向外层同步全屏状态，由外层同时控制模块导航栏和状态栏背后的容器底色；退出或销毁子页面时清理该状态。
- 外层容器和子页面须明确安全区与窗口 inset 的处理归属，避免状态栏底色断层、重复留白或内容被遮挡。

## 4. 页面验收清单

- [ ] 一级页浅灰头部上接状态栏，白色内容下接模块导航栏；固定区与滚动区分界准确。
- [ ] 二级及更深页面白色头部上接状态栏，下方浅灰内容铺满可用区域；模块导航栏及其占位均已消失。
- [ ] 日历、会议室日期栏保持白色，时间网格中的状态色仍能正确表达信息。
- [ ] 滚动、空态、加载态、错误态与不足一屏时，背景分区仍然成立。
- [ ] 顶栏返回、系统返回、模块切换后，页面配色和模块导航栏正确恢复。
- [ ] 深色主题使用对应 token，状态栏文字和图标清晰可读。

以上布局与状态切换须在模拟器或真机上走查；`checkDesignTokens` 只覆盖其已有静态规则，不能替代本清单的视觉与交互验收。
