# We Meet Android 设计规范

> 这份文档的目的不是"好看"，而是**可预测**：同一个东西在任何页面都长一样、
> 按一下都是同一个结果。规范只写有约束力的部分——能在代码里强制的，一律
> 指向代码；只能靠人守的，写清楚为什么。

## 0. 采用哪套规范

| 层 | 采用 | 说明 |
|---|---|---|
| 视觉与组件 | **Material Design 3** | Compose 的原生实现，不引入第二套视觉体系 |
| 无障碍 | **WCAG 2.2 AA** | 对比度 4.5:1、触控区 ≥48dp、TalkBack 可读 |
| 文案语感 | 中文语境参考 TDesign / Ant Design | 只借鉴措辞习惯，不借鉴视觉 |
| 自查 | Nielsen 十大可用性原则 | 见 §7 走查清单 |

**不做的事**：不照搬 iOS HIG 的视觉（返回手势、导航栏样式按 Android 走）；不
自造设计语言。M3 覆盖不到的地方才扩展，且扩展必须落到 token（§1）。

## 1. Design Token —— 唯一真源

三个文件，改样式只改这三处（都在 **`core-design`** 模块，app 与所有 feature
模块共用同一份）：

| 文件 | 管什么 |
|---|---|
| [Color.kt](../core-design/src/main/java/com/we/meet/ui/theme/Color.kt) | 所有色值字面量 |
| [Type.kt](../core-design/src/main/java/com/we/meet/ui/theme/Type.kt) | 字号阶梯 |
| [Dimens.kt](../core-design/src/main/java/com/we/meet/ui/theme/Dimens.kt) | 间距、尺寸 |

### 1.1 颜色

分三层，按优先级取用：

1. **`MaterialTheme.colorScheme.*`** —— primary / surface / onSurface / error 等。
   默认走这层。
2. **`WeMeetTheme.extras.status.*`** —— M3 给不了的状态语义：

   | token | 含义 | 典型用处 |
   |---|---|---|
   | `danger` | 不可逆、会造成损失 | 挂断、结束会议、删除、移出成员 |
   | `warning` | 需注意但不阻断 | 举手、录制中、网络差 |
   | `success` | 正向确认 | 正在说话、已连接、已保存 |
   | `accentActive` | 工具处于开启态 | 字幕开、共享中 |

   每档配 `xxxContainer`（浅底）和 `onXxxContainer`（浅底上的文字）。
   `danger` 另有 `onDanger`，用于实底按钮。

   > **按语义选，不要按颜色选。** 想要个红按钮 ≠ 该用 `danger`。`danger` 的
   > 含义是"这一步会造成损失"，用了它就该配二次确认。

3. **`WeMeetTheme.extras.room.*`** —— 会中界面专用（`tileBackground`、
   `speakingRing`、`overlayScrim`、`subtitleText`、`avatarFallback`）。
   会中永远深色，这几个值不分深浅色主题。

4. **`WeMeetTheme.extras.rsvp.*`** —— 日历表态四态四色。色值与 Web 的
   `calendarGridOverrides.css` 一一对应，**改色必须两端同步**。

   > 日历目前有**两处** Web ↔ App 强耦合，改一边必须改另一边：
   > 表态四色（上面这条），以及**已结束日程的压淡规则**（App 在
   > `TimeGrid.kt` 的 `fillDim` / `AgendaCard`，Web 在
   > `calendarGridOverrides.css` 的 `.wm-past` 段）。后者的规矩是
   > **只压填充、不压文字**——整块降透明会把标题一起压到 2 点几比一，
   > 两边都犯过这个错。

5. **`WeMeetTheme.extras.im.*` / `.aiCall.*`** —— 聊天与通话专用。
   **通话的红/绿全 App 只有一套**（`im.callHangUp` / `im.callAccept`），
   AI 通话页取的是同两个值——同一个动作不该有两种颜色。改它们之前先算
   对比度，接听绿离 3:1 门槛只差一点，理由和数字都在 Color.kt。

   `aiCall.control` 这组（麦克风 / 视频切换的圆底与图标）**跟随主题**，
   不是固定浅色；只有 `aiCall.controlOnDark` 恒深色，用于控件压在摄像头
   画面上的那种情况——判断收在组件的 `onDark` 参数里，和顶栏 / 状态条
   同一套逻辑，调用处不要自己 `isSystemInDarkTheme()`。

**禁止**：业务代码里出现 `Color(0xFF…)` 字面量。需要新颜色 → 先想能不能复用
现有 token；确实不能 → 加到 Color.kt 的 `Light…`/`Dark…` 对 + 挂进
`WeMeetExtras`，**不要在调用处 `if (isSystemInDarkTheme())`**。

### 1.2 字体

用 M3 的 15 档 type scale，一个字号也不自定义。常用对应：

| token | 字号 | 用在 |
|---|---|---|
| `headlineSmall` | 24 | 页面大标题、空态主文案 |
| `titleLarge` | 22 | TopAppBar 标题 |
| `titleMedium` | 16 | 卡片/列表行主标题 |
| `titleSmall` | 14 | 分组小标题 |
| `bodyLarge` | 16 | 正文 |
| `bodyMedium` | 14 | 次要正文、列表行副标题 |
| `bodySmall` | 12 | 辅助说明、时间戳 |
| `labelLarge` | 14 | 按钮文字 |
| `labelSmall` | 11 | 最小可读标签 |

补充两档在 `WeMeetTextStyles`：`LabelTiny`（10sp，仅限受限空间的非关键信息，
如画面角标、未读数）、`CodeDisplay`（会议号/验证码展示）。

**禁止**：业务代码里出现 `fontSize = N.sp`。
**下限**：正文和任何可点击文字不得小于 11sp。

### 1.3 间距

8dp 栅格，取值一律来自 `Dimens`：

```
SpaceXxs 2   SpaceXs 4   SpaceS 8   SpaceM 12
SpaceL 16    SpaceXl 24  SpaceXxl 32
ScreenPadding 16 · ButtonHeight 52 · MinTouchTarget 48
IconSmall 18 · IconMedium 24 · IconLarge 28
```

- 页面左右边距一律 `Dimens.ScreenPadding`，不要各写各的 `16.dp`
- 列表项之间 `SpaceS`，分组之间 `SpaceL`，页面区块之间 `SpaceXl`
- `SpaceXxs`/`SpaceXs` 是图标与文字贴合用的次栅格例外，别拿来排版

**禁止**：业务代码里出现裸 `N.dp`（`Modifier.size` 传 token；确需精确视觉
微调的，注释说明原因）。

## 2. 共享组件 —— 规范的执行者

在 [core-design 的 ui/components/](../core-design/src/main/java/com/we/meet/ui/components/)。
**新页面必须用这些，不要重新手写。**

| 组件 | 替代 | 保证 |
|---|---|---|
| `WeMeetTopBar` | 直接调 M3 `TopAppBar` | 返回键图标 + TalkBack 文案统一；标题单行省略号 |
| `WeMeetLoading` | 手写 `CircularProgressIndicator` | 位置统一居中 |
| `WeMeetEmptyState` | 手写空态 Column | 图标/主文案/说明/动作的层级与间距统一 |
| `WeMeetErrorState` | 手写错误 Column | **强制带重试** |
| `PrimaryButton` / `SecondaryButton` / `DangerButton` | 手写 `Button` | 高度统一 52dp；主按钮内置 loading 态 |

### 2.1 三态必须成组处理

```kotlin
when {
    state.loading && state.items.isEmpty() -> WeMeetLoading()
    state.error   && state.items.isEmpty() -> WeMeetErrorState(onRetry = vm::refresh)
    state.items.isEmpty()                  -> WeMeetEmptyState(title = …)
    else -> /* 列表 */
}
```

注意三处 `items.isEmpty()`：**已有内容时不要用整屏态盖掉内容**。刷新失败
应该是 Snackbar，不是把用户已经看到的列表换成一张错误图。

### 2.2 按钮层级

一屏**只能有一个** `PrimaryButton`。主按钮的意义是告诉用户"就点这个"，出现
两个等于没有。

### 2.3 下拉菜单：宽度不要绑死在锚点上

`ExposedDropdownMenu` 的 `matchTextFieldWidth` **默认 true**——它的设计前提是
锚点为一个 `fillMaxWidth()` 的输入框。但我们大量把它挂在窄按钮上（设置行右侧
的"不重复 ▲"），菜单于是被强行约束成按钮那么窄，"每个工作日"当场折成两行。

判断规则：

| 锚点 | 怎么写 |
|---|---|
| `fillMaxWidth()` 的 `TextField` / `OutlinedTextField` | 保持默认，跟宽是本分 |
| `TextButton` / 图标 / 一段文字 | `matchTextFieldWidth = false`，菜单按内容自适应 |

窄锚点的菜单项再加 `Text(…, softWrap = false)` 作为第二道护栏——显式声明
"这项就是单行"，将来菜单又被什么约束压窄也不会折行。代价是超长文案会被裁切
而非折行，所以**只用于枚举型选项**，不要用在用户生成的长文本上。

## 3. 页面结构

标准骨架：

```kotlin
Scaffold(
    topBar = { WeMeetTopBar(title = …, onBack = onBack) },
) { padding ->
    Box(Modifier.fillMaxSize().padding(padding)) { … }
}
```

- **顶栏**：tab 根页面不传 `onBack`；二级页必传。右侧 actions 超过 3 个收进溢出菜单
- **返回**：系统返回键与顶栏返回键行为必须一致
- **滚动**：内容可能超屏的一律可滚动，别假设放得下
- **键盘**：有输入框的页面处理 ime padding，不要让键盘盖住主按钮

## 4. 文案

- **所有用户可见文字进 `strings.xml`**，中英双份（`values/` + `values-zh-rCN/`）。
  业务代码里不许出现中文字面量
- 空态文案：说清"现在什么情况"+"怎么才能有"，不写"暂无数据"这类系统腔
- 错误文案：说人话 + 给出路。能给具体原因就给（"该会议已结束"优于"加载失败"）
- 破坏性操作的确认弹窗：标题说清后果，确认按钮写动作名（"结束会议"）而非"确定"

## 5. 无障碍

分两类写，因为混在一起会让人把"我们自订的更严标准"当成上架卡点，
把力气花错地方。

### 5.1 WCAG 2.2 AA —— 合规底线，不许破

- **对比度**：正文 4.5:1（SC 1.4.3）；**图标、按钮底色、状态指示等非文本
  元素 3:1**（SC 1.4.11）。新增颜色对**必须实算**，不要凭眼睛判断——
  白图标压在"看起来挺深"的绿上只有 2.6:1 这种事真的发生过（见 Color.kt
  里通话红绿的记录）
- **触控区 ≥ 24×24**（SC 2.5.8）
- **所有功能性图标带 `contentDescription`**（SC 1.1.1），字符串走
  `strings.xml` 的 `cd_` 前缀。纯装饰图标显式传 `null`（表示"有意不读"，
  而非忘了写）
- **不靠颜色单独传达信息**（SC 1.4.1）：静音状态除了变红，还要有斜杠图标

### 5.2 本规范自订（比 AA 严，是目标不是卡点）

- **触控区 ≥ `Dimens.MinTouchTarget`（48dp）** —— Material 的建议值，也是
  WCAG **AAA** 的量级。图标按钮视觉可以小，热区不该小。
  `Dimens.IconButtonCompact`（32dp）是这条的存量例外，AA 是过的
- **正文与可点击文字 ≥ 11sp**（§1.2）—— WCAG **没有**最小字号条款，
  SC 1.4.4 管的是"能放大到 200% 不丢内容"，`sp` 跟随系统缩放本身就满足。
  这条纯粹是可读性要求。`WeMeetTextStyles.LabelMicro`（9sp）是存量例外
- 深浅色两套都要过一遍

## 6. 动效

- 用 M3 默认时长与曲线，别自定义
- 页面转场统一，同层级页面用同一种
- 状态变化（静音、举手）要有过渡，不要瞬变
- 加载超过 ~300ms 才显示 loading，避免闪烁

## 7. 提交前走查清单

新增/改动页面时逐条过：

- [ ] 没有裸 `Color(0xFF…)` / `N.sp` / 未经 token 的 `N.dp`
- [ ] 顶栏用 `WeMeetTopBar`，加载/空/错误三态用共享组件且成组处理
- [ ] 一屏只有一个主按钮；破坏性操作用 `DangerButton` 且有二次确认
- [ ] 用户可见文字全在 `strings.xml`，中英齐全
- [ ] 图标有 `contentDescription`（装饰性显式 `null`），触控区 ≥48dp（§5.2）
- [ ] 新增颜色对**算过**对比度：正文 4.5:1、图标/底色 3:1（§5.1，实算别靠眼）
- [ ] 深色模式过了一遍
- [ ] 内容可滚动；有输入框的处理了键盘遮挡
- [ ] 长文本/长昵称不会撑破布局
- [ ] 下拉菜单挂在窄锚点上时给了 `matchTextFieldWidth = false`（§2.3），选项不折行

## 9. 护栏（自动检查）

规范靠人守一定会漂，所以本文档 §1–§4 的硬性部分由构建强制：

```bash
./gradlew checkDesignTokens                    # 检查（提交前 / CI）
./gradlew checkDesignTokens -Pdesign.baseline  # 重写基线
```

实现在 [DesignLintTask.kt](../buildSrc/src/main/kotlin/DesignLintTask.kt)，覆盖 9 条规则：
`raw-color` · `raw-font-size` · `raw-dimen` · `raw-topbar` · `cjk-literal` ·
`text-color-slot` · `dropdown-menu-width` · `icon-button-description` ·
`icon-button-touch-target`。扫描前会剥掉注释——本仓库注释是中文
写的，不剥全是误报。

### `text-color-slot`：文字色必须取前景槽位

M3 的 ColorScheme 是**成对**的，每个「面」配一个 `on-` 色，配对关系本身就是
对比度保证。拿面色当文字色，对比度就是碰运气——这一类我们踩过四次：月网格
今天那格取错 `on-` 色（1.2:1）、非本月日期用 `outlineVariant`（1.66:1）、
全仓 36 处拿 `outline` 当次要文字（4.44:1）、提醒角标文字和底同色（2.07:1）。

所以 `color =` / `tint =` 右边**不许**出现 `background` / `surface*` /
`*Container` / `outline` / `outlineVariant` / `scrim` / `inverseSurface`。
次要文字用 `onSurfaceVariant`，强调文字用 `primary` / `error`。

三种写法都认——直接赋值、`= when { … }` 的分支、`= if (…) { … }` 的分支。
后两种是重点：月网格那个 bug 正是藏在 `when` 分支里，只看 `color =` 那行
看不见。这几处**不算**违规，因为它们本来就不是文字色：

- `Surface(color = …)`——M3 的 Surface 拿 `color` 当底色，前景走 `contentColor`
- `HorizontalDivider(color = …)`、`.border(…)`、进度条、Canvas 绘制
- `.background(color = …)`

判断外层调用靠**缩进**（缩进更浅且带 `(` 的第一行就是包着它的调用），所以
对齐不规范的代码可能判错——真遇上写 `// design-exempt: 理由`。

两条规则管不到、只能靠人算的：**颜色是不是真的够对比度**（规则只查槽位来源，
不查数值），以及**文字与它自己的底同色**（如 `color = X` + 底 `X.copy(alpha=.14f)`，
提醒角标就是这么错的）。新增颜色对照 §7 清单实算。

### `dropdown-menu-width`：菜单宽度不绑死在窄锚点上

见 §2.3。规则按 `ExposedDropdownMenuBox { … }` **整块**判，而不是按单行——
"锚点是什么"这个信息根本不在 `ExposedDropdownMenu(` 那一行上，它在十几行之前：

- 块里出现过 `*TextField(` → 认为锚点是输入框，跟宽是本分，放过
- 否则块里必须出现 `matchTextFieldWidth`，缺了就报

注意写 `= true` 也算过。这条要的是**"想过这件事"**，不是某个固定值——真有
理由让菜单跟着窄按钮走，显式写出来即可，不必动用 `design-exempt`。

误判的可能：锚点是包过一层的输入框组件（名字里没有 `TextField`）时会误报，
显式补一个 `matchTextFieldWidth = true` 就好。

### 扫描范围

**全部五个模块**，`core-design` 自己也在内。它的 `theme/` 是 token 定义处、
`ui/components/` 是组件层，规则按路径豁免掉该豁免的那几条（色值/字号写在
`theme/`、`TopAppBar` 包在 `components/` 都是本分），**其余规则照常生效**——
否则往共享组件里写死一句中文、或在组件内部写裸 `.dp`，全 App 跟着错却没人报警。

### 什么时候会跑

| 时机 | 怎么接的 | 能不能绕过 |
|---|---|---|
| `./gradlew check` | 根 `build.gradle.kts` 里挂到各模块的 `check` | — |
| `git commit` | [.githooks/pre-commit](../.githooks/pre-commit)，仅在有 `.kt` 改动时触发 | `--no-verify` 可以 |
| PR / push main | [.github/workflows/design-lint.yml](../.github/workflows/design-lint.yml) | **不能** |

钩子每个克隆装一次：

```bash
./gradlew installGitHooks   # 把 core.hooksPath 指到 .githooks/
```

有意**没有**挂进 `assemble`：护栏只拦「比基线更差」，而写新页面的过程里出现
半成品的裸 `.dp` 是常态，让每次 debug 构建都红一次，结果一定是有人把它关掉。
摩擦点放在提交和 PR，不放在编辑器里。

钩子扫的是**工作区**而非暂存区——部分暂存（`git add -p`）时未暂存的改动也会
被算进来。这是为省掉「导出 index 再扫」而接受的不精确，真正的判定以 CI 为准。

### 棘轮：从 1430 到 0

立规矩时存量有 1430 处违规。一上来就硬失败等于全员绕过，规矩当场作废，
所以记一份基线 [config/design-lint-baseline.txt](../config/design-lint-baseline.txt)
**只拦增量**，再分模块把数字压下去。现在基线已经空了——护栏从"只拦增量"
自动变成了"零容忍"，因为任何违规都必然是 `0 → N` 的上升。

抬基线（`-Pdesign.baseline` 后提交）意味着你主动放宽了规范，应当在 PR 里说明理由。

### 两个豁免标记

规则会误报的地方要给出口，否则报到最后没人看，护栏就白建了。两个标记都
**必须写理由**：

| 标记 | 用于 | 例子 |
|---|---|---|
| `// i18n-exempt` | 中文**不该**进 strings.xml | 语言选择器里的「简体中文」；被 put 进 JSON 发给对方的消息占位符（本地化会让同一条消息在不同人那里语言不一） |
| `// design-exempt: 理由` | 确实不该套共享组件 | 标题位放搜索输入框的顶栏——塞进 `WeMeetTopBar` 就得开插槽，那会毁掉它对其余 20 多个页面的"标题单行截断"保证 |

`design-exempt` 认「该行」或**紧邻其上的整段注释**，理由写几行都行。
另外 `require`/`check`/`Log`/异常消息里的中文自动豁免——那些开发者才看得到。
