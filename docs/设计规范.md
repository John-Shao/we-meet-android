# We Meet Android 设计规范

> 这份文档的目的不是"好看"，而是**可预测**：同一个东西在任何页面都长一样、
> 按一下都是同一个结果。规范只写有约束力的部分——能在代码里强制的，一律
> 指向代码；只能靠人守的，写清楚为什么。

## 0. 采用哪套规范

| 层 | 采用 | 说明 |
|---|---|---|
| 视觉与组件 | **Material Design 3** | Compose 的原生实现，不引入第二套视觉体系 |
| 无障碍 | **WCAG 2.2 AA** | 对比度 4.5:1、触控区 ≥48dp、TalkBack 可读 |
| 文案语感 | 中文语境参考 TDesign / Ant Design | 只借鉴措辞习惯，不借鉴视觉 |
| 自查 | Nielsen 十大可用性原则 | 见 §7 走查清单 |

**不做的事**：不照搬 iOS HIG 的视觉（返回手势、导航栏样式按 Android 走）；不
自造设计语言。M3 覆盖不到的地方才扩展，且扩展必须落到 token（§1）。

## 1. Design Token —— 唯一真源

三个文件，改样式只改这三处：

| 文件 | 管什么 |
|---|---|
| [Color.kt](../app/src/main/java/com/we/meet/ui/theme/Color.kt) | 所有色值字面量 |
| [Type.kt](../app/src/main/java/com/we/meet/ui/theme/Type.kt) | 字号阶梯 |
| [Dimens.kt](../app/src/main/java/com/we/meet/ui/theme/Dimens.kt) | 间距、尺寸 |

### 1.1 颜色

分三层，按优先级取用：

1. **`MaterialTheme.colorScheme.*`** —— primary / surface / onSurface / error 等。
   默认走这层。
2. **`WeMeetTheme.extras.status.*`** —— M3 给不了的状态语义：

   | token | 含义 | 典型用处 |
   |---|---|---|
   | `danger` | 不可逆、会造成损失 | 挂断、结束会议、删除、移出成员 |
   | `warning` | 需注意但不阻断 | 举手、录制中、网络差 |
   | `success` | 正向确认 | 正在说话、已连接、已保存 |
   | `accentActive` | 工具处于开启态 | 字幕开、共享中 |

   每档配 `xxxContainer`（浅底）和 `onXxxContainer`（浅底上的文字）。
   `danger` 另有 `onDanger`，用于实底按钮。

   > **按语义选，不要按颜色选。** 想要个红按钮 ≠ 该用 `danger`。`danger` 的
   > 含义是"这一步会造成损失"，用了它就该配二次确认。

3. **`WeMeetTheme.extras.room.*`** —— 会中界面专用（`tileBackground`、
   `speakingRing`、`overlayScrim`、`subtitleText`、`avatarFallback`）。
   会中永远深色，这几个值不分深浅色主题。

4. **`WeMeetTheme.extras.rsvp.*`** —— 日历表态四态四色。色值与 Web 的
   `calendarGridOverrides.css` 一一对应，**改色必须两端同步**。

**禁止**：业务代码里出现 `Color(0xFF…)` 字面量。需要新颜色 → 先想能不能复用
现有 token；确实不能 → 加到 Color.kt 的 `Light…`/`Dark…` 对 + 挂进
`WeMeetExtras`，**不要在调用处 `if (isSystemInDarkTheme())`**。

### 1.2 字体

用 M3 的 15 档 type scale，一个字号也不自定义。常用对应：

| token | 字号 | 用在 |
|---|---|---|
| `headlineSmall` | 24 | 页面大标题、空态主文案 |
| `titleLarge` | 22 | TopAppBar 标题 |
| `titleMedium` | 16 | 卡片/列表行主标题 |
| `titleSmall` | 14 | 分组小标题 |
| `bodyLarge` | 16 | 正文 |
| `bodyMedium` | 14 | 次要正文、列表行副标题 |
| `bodySmall` | 12 | 辅助说明、时间戳 |
| `labelLarge` | 14 | 按钮文字 |
| `labelSmall` | 11 | 最小可读标签 |

补充两档在 `WeMeetTextStyles`：`LabelTiny`（10sp，仅限受限空间的非关键信息，
如画面角标、未读数）、`CodeDisplay`（会议号/验证码展示）。

**禁止**：业务代码里出现 `fontSize = N.sp`。
**下限**：正文和任何可点击文字不得小于 11sp。

### 1.3 间距

8dp 栅格，取值一律来自 `Dimens`：

```
SpaceXxs 2   SpaceXs 4   SpaceS 8   SpaceM 12
SpaceL 16    SpaceXl 24  SpaceXxl 32
ScreenPadding 16 · ButtonHeight 52 · MinTouchTarget 48
IconSmall 18 · IconMedium 24 · IconLarge 28
```

- 页面左右边距一律 `Dimens.ScreenPadding`，不要各写各的 `16.dp`
- 列表项之间 `SpaceS`，分组之间 `SpaceL`，页面区块之间 `SpaceXl`
- `SpaceXxs`/`SpaceXs` 是图标与文字贴合用的次栅格例外，别拿来排版

**禁止**：业务代码里出现裸 `N.dp`（`Modifier.size` 传 token；确需精确视觉
微调的，注释说明原因）。

## 2. 共享组件 —— 规范的执行者

在 [ui/components/](../app/src/main/java/com/we/meet/ui/components/)。
**新页面必须用这些，不要重新手写。**

| 组件 | 替代 | 保证 |
|---|---|---|
| `WeMeetTopBar` | 直接调 M3 `TopAppBar` | 返回键图标 + TalkBack 文案统一；标题单行省略号 |
| `WeMeetLoading` | 手写 `CircularProgressIndicator` | 位置统一居中 |
| `WeMeetEmptyState` | 手写空态 Column | 图标/主文案/说明/动作的层级与间距统一 |
| `WeMeetErrorState` | 手写错误 Column | **强制带重试** |
| `PrimaryButton` / `SecondaryButton` / `DangerButton` | 手写 `Button` | 高度统一 52dp；主按钮内置 loading 态 |

### 2.1 三态必须成组处理

```kotlin
when {
    state.loading && state.items.isEmpty() -> WeMeetLoading()
    state.error   && state.items.isEmpty() -> WeMeetErrorState(onRetry = vm::refresh)
    state.items.isEmpty()                  -> WeMeetEmptyState(title = …)
    else -> /* 列表 */
}
```

注意三处 `items.isEmpty()`：**已有内容时不要用整屏态盖掉内容**。刷新失败
应该是 Snackbar，不是把用户已经看到的列表换成一张错误图。

### 2.2 按钮层级

一屏**只能有一个** `PrimaryButton`。主按钮的意义是告诉用户"就点这个"，出现
两个等于没有。

## 3. 页面结构

标准骨架：

```kotlin
Scaffold(
    topBar = { WeMeetTopBar(title = …, onBack = onBack) },
) { padding ->
    Box(Modifier.fillMaxSize().padding(padding)) { … }
}
```

- **顶栏**：tab 根页面不传 `onBack`；二级页必传。右侧 actions 超过 3 个收进溢出菜单
- **返回**：系统返回键与顶栏返回键行为必须一致
- **滚动**：内容可能超屏的一律可滚动，别假设放得下
- **键盘**：有输入框的页面处理 ime padding，不要让键盘盖住主按钮

## 4. 文案

- **所有用户可见文字进 `strings.xml`**，中英双份（`values/` + `values-zh-rCN/`）。
  业务代码里不许出现中文字面量
- 空态文案：说清"现在什么情况"+"怎么才能有"，不写"暂无数据"这类系统腔
- 错误文案：说人话 + 给出路。能给具体原因就给（"该会议已结束"优于"加载失败"）
- 破坏性操作的确认弹窗：标题说清后果，确认按钮写动作名（"结束会议"）而非"确定"

---

## 5. 无障碍（WCAG 2.2 AA，上架合规项）

- **触控区 ≥ `Dimens.MinTouchTarget`（48dp）**。图标按钮视觉可以小，热区不许小
- **所有功能性图标带 `contentDescription`**，字符串走 `strings.xml` 的 `cd_` 前缀。
  纯装饰图标显式传 `null`（表示"有意不读"，而非忘了写）
- **对比度**：正文 4.5:1，大字/图标 3:1。新增颜色对必须校验
- **不靠颜色单独传达信息**：静音状态除了变红，还要有斜杠图标
- 深浅色两套都要过一遍

---

## 6. 动效

- 用 M3 默认时长与曲线，别自定义
- 页面转场统一，同层级页面用同一种
- 状态变化（静音、举手）要有过渡，不要瞬变
- 加载超过 ~300ms 才显示 loading，避免闪烁

---

## 7. 提交前走查清单

新增/改动页面时逐条过：

- [ ] 没有裸 `Color(0xFF…)` / `N.sp` / 未经 token 的 `N.dp`
- [ ] 顶栏用 `WeMeetTopBar`，加载/空/错误三态用共享组件且成组处理
- [ ] 一屏只有一个主按钮；破坏性操作用 `DangerButton` 且有二次确认
- [ ] 用户可见文字全在 `strings.xml`，中英齐全
- [ ] 图标有 `contentDescription`（装饰性显式 `null`），触控区 ≥48dp
- [ ] 深色模式过了一遍
- [ ] 内容可滚动；有输入框的处理了键盘遮挡
- [ ] 长文本/长昵称不会撑破布局

## 9. 护栏（自动检查）

规范靠人守一定会漂，所以本文档 §1–§4 的硬性部分由构建强制：

```bash
./gradlew checkDesignTokens                    # 检查（提交前 / CI）
./gradlew checkDesignTokens -Pdesign.baseline  # 重写基线
```

实现在 [DesignLintTask.kt](../buildSrc/src/main/kotlin/DesignLintTask.kt)，覆盖 5 条规则：
`raw-color` · `raw-font-size` · `raw-dimen` · `raw-topbar` · `cjk-literal`。
扫描前会剥掉注释——本仓库注释是中文写的，不剥全是误报。

### 为什么是"棘轮"而不是硬失败

立规矩时存量已有 1430 处违规。一上来就报错等于全员绕过，规矩当场作废。
所以记一份基线 [config/design-lint-baseline.txt](../config/design-lint-baseline.txt)，
**只拦增量**：

- 新代码必须干净——任何文件违规数上升就构建失败
- 存量随缘迁移，迁一处基线降一处，不可能反弹
- 违规数下降时任务会提示你重写基线，把数字锁死

抬基线（`-Pdesign.baseline` 后提交）意味着你主动放宽了规范，应当在 PR 里说明理由。
