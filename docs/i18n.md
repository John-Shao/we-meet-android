# Localisation

Five UI languages ship, mirroring the Web frontend's i18n bundle. `en` is the
default in `res/values/`; everything else lives in a `values-<locale>/`
directory next to it.

| UI language | Resource directory | Form of address |
|---|---|---|
| English (default) | `res/values/` | — |
| 简体中文 | `res/values-zh-rCN/` | — |
| Deutsch | `res/values-de/` | formal **Sie** |
| Français | `res/values-fr/` | formal **vous** |
| Nederlands | `res/values-nl/` | informal **je** |

The language picker is `SettingsScreen.LANGUAGE_OPTIONS`. Adding a language
means changing both that list and `FULL_LOCALES` in `scripts/android_i18n.py`.

## Rules

1. **Chinese copy goes in `values-zh-rCN/`, never in `values-zh/`.** A
   language-only directory also matches zh-TW/zh-HK/zh-SG, so a stray file there
   shows those devices a few Simplified strings above an otherwise English UI
   while zh-CN is unaffected. That directory was created by accident twice
   (`d3d82d1b`, then the voice-tools POC) and is gone; the gate now fails on a
   partial language-only overlay.
2. **Every supported locale must be complete.** A missing key falls back to
   English at runtime, which reads as a half-translated screen.
3. **Do not rewrite existing translations to match a new one.** Reuse the
   established term (see the glossary below) instead.
4. Chinese is the **semantic reference**: the product was written in Chinese
   first, and the English copy is occasionally looser than the Chinese.

## The gate

```bash
python scripts/i18n.py check                  # exit 1 if a locale is wrong
python scripts/i18n.py check --show-warnings  # list every advisory warning
python scripts/i18n.py check --json           # machine-readable report
python scripts/i18n.py check --locale de      # one locale
python scripts/i18n.py check --module app     # one module
```

It errors on: a missing key, a key that no longer exists in English, a broken
format specifier (`%1$s` dropped or renumbered), a `plurals` entry without
`other`, a `string-array` whose item count changed, an unescaped apostrophe, an
undeclared locale directory, and a partial language-only overlay.

Warnings are advisory and deliberately low-noise: values still identical to
English, and text-QA nits (edge whitespace, a sentence missing its final
punctuation). The text heuristics skip CJK values, because Chinese punctuation
and fullwidth brackets are not defects.

### The identical-value baseline

Cognates (`Host` in German, `Document` in French), language endonyms (`Hindi`,
`Urdu`) and format-only strings (`%1$d min`) are legitimately identical to
English. `scripts/i18n-allow-identical.json` lists the reviewed ones so the one
warning that matters — a value nobody translated — stands out. Keep it small:
adding a real gap to it hides it.

Legitimate CLDR differences are warnings, not errors: French declares a `many`
plural quantity that English does not, and zh-CN declares `other` alone.

### The advisory report

`check` proves completeness and structure. The softer defects a translation pass
leaves behind need a human eye, so they live in a separate, never-failing report:

```bash
python scripts/i18n.py report                  # every locale
python scripts/i18n.py report --locale de
python scripts/i18n.py report --json
```

It lists three things per locale:

* **consistency** — the same English *and* Chinese source rendered more than one
  way, naming the keys behind each rendering. This is what surfaced `Retry` as
  both `Erneut` and `Erneut versuchen`, and two French terms for 智能纪要. A split
  is only a defect when both variants mean the same thing; see § Review policy
  for the ones that are correct.
* **register** — strings addressing the user in the wrong form for the locale.
* **length** — translations far longer than English. German and French run about
  30% longer by nature, so this is a "check the layout" list, not a defect list.

It exits 0 even when it finds something: the lists need judgement, so they must
not break a build. Run it when reviewing copy, not in CI.

## Translating a new language (or refilling a gap)

```bash
# 1. extract what is missing, with the Chinese reference alongside
python scripts/i18n.py plan --locale es

# 2. translate each .i18n-work/es/<module>__<file>.src.xml into a sibling
#    .out.xml: same keys, same order, same element kinds, only the text changes

# 3. merge the bundles back (byte-preserving and idempotent)
python scripts/i18n.py merge

# 4. prove it
python scripts/i18n.py check
```

`plan` writes `<module>__<file>.src.xml` (English) plus, when the reference
locale covers every missing key, `<module>__<file>.ref.xml` (Simplified
Chinese). Bundles carry the module name because several modules own a
`strings.xml`. The work directory defaults to `.i18n-work/`, which is ignored by
git.

`merge` never rewrites existing bytes: it inserts each new entry next to its
nearest preceding English neighbour (or directly under `<resources>`), carries
the English comment block across, skips keys the target already has, and writes
LF. A partial or repeated run is therefore safe.

## Glossary

Consistency matters more than elegance here; these are the terms the shipped
copy already uses. Diverging within one language is the most common review
complaint.

| English | German | French | Dutch |
|---|---|---|---|
| meeting | Meeting | réunion | vergadering |
| recording | Aufnahme | enregistrement | opname |
| transcript | Transkript | transcription | transcriptie |
| meeting minutes (纪要) | Zusammenfassung | compte rendu | notulen |
| summary / overview (摘要/概要) | Übersicht | résumé | samenvatting |
| participant | Teilnehmer | participant | deelnemer |
| speaker (person) | Sprecher | intervenant | spreker |
| host | Host | hôte | host |
| task | Aufgabe | tâche | taak |
| trash | Papierkorb | corbeille | prullenbak |
| document | Dokument | document | document |
| calendar | Kalender | agenda | agenda |
| notification | Benachrichtigung | notification | melding |
| AI | KI | IA | AI |

Note that 纪要 and 摘要 are different concepts: the minutes are the per-meeting
artefact, the summary is the live/rolling text. Keep the two terms apart, and
follow the Chinese when the English is ambiguous. The *smart minutes* feature
label is a fixed phrase per language: `Intelligente Zusammenfassung` /
`Compte rendu IA` / `Slimme notulen`. French uses the shipped `Compte rendu IA`
rather than a literal rendering of "smart".

## Review policy

A native review of all three languages settled these rules. Apply them to new
copy; they are what the shipped strings now do.

* **Register is enforced**, not merely preferred: German is formal **Sie**
  throughout, Dutch informal **je**, French **vous**. A shipped string that
  addressed the user the other way was corrected rather than tolerated.
* **One term per concept.** When the same English and Chinese source had been
  rendered two ways, the Simplified Chinese decided, then the shipped wording.
* **Some splits are correct and must stay.** Do not "fix" these:
  * grammatical gender or number agreeing with the noun the string modifies
    (`Annulé` for a call, `Annulée` for a run; `Aucun` / `Aucune`);
  * the microphone versus the audio output (`Couper le micro` vs
    `Couper le son`, `Réactiver le micro` vs `Réactiver le son`);
  * a permission *dropdown* (`Lesen` / `Bearbeiten`, `Lecture` / `Modification`)
    versus a capability *list* (`Kann lesen`, `Peut lire`) — both are the
    convention in their own context;
  * Dutch call verbs versus event verbs (`Weigeren` / `Geweigerd` for a call,
    `Afwijzen` / `Afgewezen` for an invitation).

### Apostrophes

French uses the typographic apostrophe **`’`** (U+2019) throughout, matching the
Web frontend's French bundle (558 of them, and not one escaped ASCII form):

    l’enregistrement        not   l\'enregistrement

Android requires an escape only for the **ASCII** apostrophe, so `’` needs no
backslash and cannot be broken by a forgotten one — a bare `'` is a build error
unless the whole value is wrapped in double quotes. Only the French copy has been
converted so far; English (45 escaped vs 22 typographic) and Dutch (5 vs 18)
still mix the two forms, and are worth aligning the same way when they are next
touched.

Do not confuse this with `\"`, which escapes a literal double quote. A value may
legitimately be wrapped in quotes to preserve leading or trailing spaces — the
English `im_departed_suffix` is `" (left)"` for exactly that reason.

## Running the tests

```bash
python -m unittest discover -s scripts -p 'test_*.py'
```

`scripts/test_android_i18n.py` covers the parser edge cases that have actually
bitten (`string-array` mis-parsed as `string`, a multi-line comment truncated),
the checker, the allowlist, the merge semantics (anchor placement, idempotency,
comment carry-over, LF), and asserts that this repository passes its own gate.
