# 录音回放短暂网络波动导致中断

用户反馈录音回放频繁显示「播放已中断或暂时不可用」。Android 日志主要为 AppOps attributionTag 提示，没有播放器失败原因；提供的后端日志均为 HTTP 200，`200 504` 中的 504 是响应字节数。这些日志不足以确定每次现场中断的具体触发点。

代码走查发现两条可导致误中断的路径：

1. 播放权限核验串行调用记录、capture 和 manifest 三个接口，心跳却只允许整组请求耗时 2.5 秒。移动网络多次往返延迟会累加。
2. 预加载分片的一次传输失败会立即取消整个播放协程，正在播放的已验证音频也会被停止。

## 修改

- 三个独立鉴权的元数据 GET 并行执行，所有身份、来源、保留模式、capture revision 和 manifest 校验保留。
- 心跳提前至每次成功核验后 1 秒发起，单次核验超时仍为 2.5 秒；短暂超时或网络错误允许有限重试。原有 5 秒有效核验窗口保持不变，失败不延长该窗口。
- 播放中的幂等读取最多尝试三次，间隔 250 / 500 毫秒，仅针对传输错误、请求超时及 HTTP 408/500/502/503/504。401/403/404/409/429、音频校验失败不重试。
- 取消播放、切换账号、退到后台或音频焦点丢失仍停止并清理缓冲，不自动恢复已停止的播放。
- 等待分片时显示缓冲状态；用户点击重试重新加载后保留中断位置，继续播放仍由用户发起。
- 添加 `CapturePlayback` 日志，只记录固定错误分类或 HTTP 状态，不打印异常原文、音频内容、URL、记录 ID 或密钥。

## 验证

- 22 项 JVM 测试通过：CapturePlaybackEngineTest 11 项、CapturePlaybackRepositoryTest 8 项、PlaybackReadRetryTest 3 项。
- 新增慢网络验证：三个元数据接口各延迟 1.1 秒，整组核验仍在 2.5 秒内完成；心跳单次超时能在有效窗口内恢复。
- 验证分片首次失败后重试同一分片并正常继续、持续断网停止、权限和校验失败不重试、取消后不再发送下一次重试，以及音频缓冲清零。
- 主代码和 Android 测试代码编译通过，未执行真机回归。

仅需重新构建并覆盖安装 Android App；后端接口及配置不变。部署后使用原录音连续播放并测试跳转、倍速和短暂弱网；若仍中断，提供 `adb logcat -s CapturePlayback` 中的固定错误分类，可进一步区分网络、HTTP 拒绝及播放输出问题。
