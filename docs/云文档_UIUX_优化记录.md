# 原生云文档 UI / UX 优化

日期：2026-09-07。范围：Android 原生列表、阅读、搜索、评论、分享、版本、子文档、移动及标题表单。

## 阅读优先的文档操作布局（2026-09-07）

本节取代之前阅读页底部常驻操作栏和右上角下拉菜单的布局。

- 顶栏保留返回、随正文滚动显示的文档标题、分享到聊天及更多。可读取文档时可直接进入聊天分享，不增加分享首页。
- 取消评论、版本、分享、编辑的固定底栏。编辑改为右下角悬浮按钮，仅有编辑权限时出现；正文末尾按按钮实测高度增加滚动留白，避免末段内容被遮挡。
- 更多改为原生底部抽屉：顶部文档标题及更新时间；评论、收藏/取消收藏、版本为快捷区；链接分享和成员与权限为协作组；重命名、子文档、移动、创建副本、网页版入口为管理组；删除独立放在底部并继续二次确认。
- 服务端能力控制动作是否出现。收藏操作保持抽屉打开并显示更新后的状态，其余动作先收起当前抽屉再进入目标页面，避免多个抽屉重叠。链接分享、成员与权限继续使用独立页面。
- 抽屉列表可滚动，快捷按钮文字可换行，标题最多两行；系统返回关闭抽屉。原有加载失败、无权限申请、刷新和正文轮询保留。
- 范围仅 Android 界面及阅读容器留白，不修改后端接口、权限模型或 PC Web 页面。

验证：`:feature-docs:testDebugUnitTest`（17 项）、`:app:assembleDebug` 和 `checkDesignTokens` 通过。Pixel 8 模拟器已安装新 APK，检查阅读页、更多抽屉、顶栏聊天选择入口、更多到链接分享/评论的切换及返回；1.5 倍字体、横屏和深色模式下可滚动到末尾操作。检查期间未发送聊天消息或修改文档内容、权限；完成后恢复模拟器原有显示设置。只读账号的操作显隐本轮通过代码审查，未另行切换账号实测。

## 最新调整：分享按任务拆分（2026-09-07）

后续补充：聊天中自己发送的文档卡片新增“会话权限”，可查询服务端设置并保存“可阅读 / 可编辑”。当前无管理权时不提供保存；加载或保存失败可重试，保存不重发卡片。同一文档、会话、分享者共用一项授权来源，允许降低该聊天来源，但保留其他来源的更高权限。旧卡片已有授权无法追溯来源，作为独立基线保留。此补充需要 Docs `0034_document_chat_permissions` 迁移，取代下文此前“无数据库迁移”的结论。

本节取代下文历史记录中的分享首页、立即保存链接范围和固定只读聊天授权设计。

- 阅读页底部直接“分享到聊天”；更多菜单分别进入“链接分享”和“成员与权限”，取消混合分享首页。
- 聊天选择复用已有会话、联系人、多选和建群流程；选定后统一确认文档、目标和授权类型，默认“可阅读”，可选“可编辑”。无成员管理能力时只发送卡片，说明接收者继续按原有权限访问。
- 服务端以真实操作者检查授权能力；新增或升级授权不降低已有更高权限，不调整链接范围。目标为分享当时的会话成员，不自动绑定未来入群或退群变化。
- 卡片发送和授权分开确认及重试。新协议要求明确的角色与完成标记，旧服务不能被误判为已完成编辑授权。
- 链接页先加载最新设置；范围和角色为草稿，点击“保存并复制链接”后才更新。失败保留草稿，关闭丢弃未提交修改，旋转保留。无配置权限者仅可复制当前链接。
- “仅已获授权用户”隐藏链接角色，继续使用每位用户已有权限；其他范围按服务端可选角色展示。认证范围更名为“已登录用户”，避免暗示后端存在企业隔离。
- 成员页独立承载角色、移除、邀请和离开文档。邀请为其子页，返回仍保留未提交输入。

发布顺序：Docs backend → Meet backend → Android APK；无数据库迁移，PC Web 页面未改。授权接口详见 `we-meet-docs/docs/chat-sharing-permissions.md`。

验证：Android 构建、设计 token 检查、17 项 Docs 测试及 5 项发送流程测试通过；隔离数据库下 Docs 授权 11 项、Meet 授权与响应契约 13 项测试通过。模拟器检查会话选择与角色确认、链接草稿及关闭恢复、独立成员入口；未向真实聊天发送消息或修改已有文档权限，跨账号读写仍需后端部署后联调。

## 设计取舍

- 延续 `core-design` 的 Material 3 色彩、字号、间距和触控尺寸，不另设 Docs 主题。
- 阅读以正文为主。标题与正文一起滚动，离开可视区后才进入顶栏；底栏只保留一个主动作“编辑”，评论、版本、分享使用图标与文字入口。
- 列表突出文档名称和更新时间。普通文档把收藏放入更多菜单，已收藏的文档仍显示星标。主页增加快捷筛选、当前排序和带文字的新建入口，列表尾部为悬浮按钮留出空间。
- 弹层提供统一标题、文档上下文和明确关闭按钮。长内容独立滚动，移动确认按钮与评论输入框保持可达；权限、评论动作和表情在窄屏按需换行。
- 新建、重命名、移动均在成功后关闭；失败保留输入或目标并显示错误，提交中显示进度且防止重复提交。重命名默认选中原标题，没有修改时禁用保存。

## 交互调整

| 入口 | 行为 |
|---|---|
| 搜索 | 自动聚焦、键盘搜索动作、清空按钮、输入引导；防抖期间显示加载而非短暂的无结果；结果行与主页保持一致 |
| 评论 | 未解决/已解决数量，独立空态；讨论边框和展开指示；折叠长评论摘要；删除收进更多菜单，保留二次确认；发送中禁用编辑，避免响应清掉新输入 |
| 评论草稿 | 继续使用已有文档级草稿存储，关闭面板不会丢失；回复仍独立保存 |
| 分享 | 内容自适应高度的简洁首屏：复制链接、访问范围摘要、协作成员数量、邀请成员；访问范围与成员管理在同一弹层内进入二级页 |
| 成员与邀请 | 成员角色与移除动作合并到角色菜单，移除仍需确认；姓名/邮箱共用一个邀请入口，先选择对象，再设置权限并明确提交；搜索门槛读取服务端配置，搜索失败可重试，失败保留表单 |
| 版本 | 说明与明确空态；整行进入预览；长列表独立滚动，保留分页入口 |
| 子文档 | 统一文件图标、两行标题、进入指示和普通分页文案 |
| 移动 | 加载失败可重试、无可用目标空态；选择行满足触控尺寸；树缩进封顶，避免深层节点挤出屏幕 |
| 编辑器不可用 | 使用用户可理解的重试/返回阅读文案，部署与协议细节保留在技术文档 |

## 验收边界

此轮不替代编辑器协议 v2 的前端部署与联调。历史版本服务当前返回空列表，只验收了版本入口、空态及列表实现，未将真实历史预览/恢复记为通过。未进行屏幕阅读器全流程、所有语言和所有折叠屏设备矩阵验收；新增表单成功写入及失败路径仍需在发布测试环境做完整业务回归。

## 分享面板简化（2026-09-07）

- 首屏取消固定 90% 屏高，按内容展开。成员加载失败不阻塞复制链接和访问范围入口，成员数量在加载完成前不显示为零。
- “链接访问范围”使用纵向单选项与范围说明，受限范围标为“仅已获授权用户”，非受限范围下再显示链接角色；仍按服务端 abilities 限制可选项，保存失败回滚。
- “成员与权限”承载成员列表、角色菜单、待接受邀请和离开文档；管理权限决定邀请入口和操作是否可用。首屏入口与二级页标题保持一致，避免将链接访问规则与具体成员授权混淆。
- “邀请成员”统一姓名/邮箱输入，搜索结果仅选择对象，不立即授权。邮箱匹配已有搜索结果时优先选择已有用户；其他有效邮箱进入发送邀请确认步骤。
- 返回上一级和旋转保留邀请对象、输入及所选角色。提交成功清理表单、进入成员页并反馈结果；失败继续保留。关闭整个分享面板不承诺恢复尚未提交的对象与角色。
- 系统返回在弹层内逐级导航；关闭按钮、点击遮罩和下滑关闭整个面板。使用弹层的 BackHandler，避免 Material 默认返回先隐藏弹层导致空白遮挡。
- 用户搜索读取 `/config/` 的 `API_USERS_SEARCH_QUERY_MIN_LENGTH`（缺省 3）；不足长度显示引导。输入变化立即清除旧结果，防止新查询期间误选旧结果。

验证：Pixel 8 / Android 16、W009。首屏约半屏；访问范围返回、角色菜单及取消移除、用户选择与角色草稿返回保留、邮箱确认页、短查询提示均通过走查。1.5 倍字体与深色模式首屏入口完整；横屏可以滚动到邀请入口，旋转后查询保留。测试未发送邀请、未修改既有成员和链接权限；设备显示设置已恢复。模拟器使用硬件键盘，完整软键盘、真实发送成功/失败、待接受邀请及非管理者角色仍需发布回归。

构建、设计 token 检查和 17 项单元测试通过，新增测试验证服务端搜索门槛契约及旧配置缺省值。本次仅修改 Android；PC Web 页面和 docs 服务无需重新部署。

## 恢复分享到聊天（2026-09-07）

- 分享首屏将“复制链接”和“分享到聊天”并排展示，后者为主动作。显示只读授权说明，明确它与单纯复制链接的区别；只有可读取文档时提供聊天分享入口。
- 原生模块通过 `onShareToChat` 将文档 ID、标题和规范 Web 链接交给宿主，先关闭分享面板，再打开已有 `ForwardPicker`；不新增 feature-docs → feature-im 依赖。
- 复用原有会话/联系人搜索、单选确认、多选、建群后转发。取消选择返回文档阅读；取消建群返回会话选择，不创建群也不发送消息。
- 原生路由与旧 WebView 入口共用 `DocChatShareFlow`，继续发送 `doc-card` v1（`doc_id`、`title`、`url`），复用既有 `grantDocAccess` 接口，未更改聊天卡片或服务端协议。
- 每个会话先确认卡片发送成功，再尝试授予该会话成员只读权限。发送和授权结果分开记录；部分发送失败时只重试未确认发送的会话，授权失败时单独重试授权，不重发已确认卡片。失败保持在结果对话框，用户可重试或关闭。
- 发送状态由 ViewModel 持有以跨旋转保留；不承诺进程被杀后的事务恢复，也不把网络超时视为确定未送达。后台是否已收消息但响应丢失，仍受现有 IM 接口的幂等能力约束。
- 重新进入原生分享面板时加载最新成员列表；WebView 兜底入口沿用权限刷新通知。

验证：构建、设计 token 检查、17 项 feature-docs 测试和 5 项新增发送流程测试通过。模拟器走查新入口、会话搜索、单选确认并取消、多选计数、建群入口并取消、返回阅读；1.5 倍字体下两个分享按钮完整显示，随后恢复字体设置。未向已有聊天发送测试消息或修改文档授权；真实发送与跨账号接收、建群成功、WebView 兜底入口仍需发布联调。仅需更新 Android APK，Docs 服务和 PC Web 无需重新部署。
